# ADR-001 — Arquitetura modular e stack TypeScript com Node.js

- **Situação:** aceita
- **Data:** 2026-11-15
- **Participantes:** Equipe Connexa

## Contexto

O projeto Connexa utiliza um repositório-modelo para padronizar o desenvolvimento das equipes. É necessário estabelecer uma arquitetura e uma stack tecnológica que facilitem a organização do código, a manutenção e o desenvolvimento incremental das funcionalidades ao longo das Sprints.

O projeto precisa de uma estrutura preparada para desenvolvimento de back-end e front-end, integração com banco de dados, testes automatizados e integração contínua.

Também é importante manter os módulos organizados e respeitar as fronteiras da arquitetura, permitindo que as funcionalidades sejam implementadas sprint a sprint a partir das Tasks do Azure Boards.

## Decisão

Adotar uma arquitetura modular utilizando TypeScript e Node.js no back-end, com NestJS 12 e Prisma 7, e React 19 com TypeScript no front-end.

A stack tecnológica será composta por:

- **Back-end:** Node.js 24 (LTS), TypeScript, NestJS 12, Prisma 7, Prisma Migrate, @nestjs/event-emitter, @nestjs/swagger e class-validator.
- **Banco de dados:** PostgreSQL 17 em contêiner.
- **Front-end:** React 19, TypeScript, Vite, React Router, TanStack Query, React Hook Form e Zod.
- **Testes:** Vitest, Supertest, Testing Library, eslint-plugin-boundaries e testes de arquitetura.
- **Ambiente:** GitHub Codespaces (Dev Container) ou máquina local com Docker.
- **Integração contínua:** GitHub Actions.

## Alternativas consideradas

| Alternativa | Por que não foi escolhida |
|---|---|
| JavaScript sem TypeScript | A equipe adotou TypeScript como padrão tecnológico do projeto. |
| Outras tecnologias de back-end | O projeto definiu Node.js e NestJS como stack de back-end. |
| Outras tecnologias de front-end | O projeto definiu React e Vite como stack de front-end. |

## Consequências

- **Positivas:** organização modular do código, padronização tecnológica entre as equipes, suporte a testes automatizados, integração contínua e desenvolvimento incremental das funcionalidades.
- **Negativas:** necessidade de conhecer e configurar diferentes tecnologias, ferramentas e bibliotecas, além de manter os testes e as fronteiras entre módulos.
- **Como verificar:** executar os testes automatizados com Vitest e Supertest, verificar as fronteiras da arquitetura com eslint-plugin-boundaries e os testes de arquitetura, além de acompanhar a execução dos checks de CI no GitHub Actions.
